SECURITY TIER 1

Tiered Permission Model

Nexus enforces four distinct privilege tiers: ReadOnly exploration, WorkspaceWrite modification, ShellExec command execution, and SystemElevated operations. High-risk actions require explicit human confirmation.

SECURITY TIER 2

Canonical Path Sandbox

Resolves every target path via kernel-level fs.realpathSync.native before access—blocking ../ traversal, NTFS Junction points, and symlink escapes into system directories like C:\Windows\System32.

SECURITY TIER 3

Allowlisted Application Control

Only pre-authorized executables and workspace roots can be spawned. Child and descendant processes are tracked as a single unit, preventing hidden background persistence.

SECURITY TIER 4

Windows JobObject Quotas

Hardware-enforced Windows JobObject containers cap per-task memory (e.g., 4 GB hard ceiling), CPU rate, and wall-clock timeouts—terminating hung or runaway trees at the kernel level.

SECURITY TIER 5

100% Loopback Local Execution

All control-plane services, SQLite WAL ledgers, and Runner daemons bind exclusively to 127.0.0.1 loopback. Zero source code, logs, or environment variables ever leave your machine.

SECURITY TIER 6

Ground-Truth Verification

The verification engine never trusts tool return codes alone. Independent probes query the OS for file byte sizes, SHA-256 digests, process exit codes, and active HWND handles after every action.

SECURITY TIER 7

Immutable Action Ledger (WAL)

Every action is persisted in an append-only SQLite WAL ledger with monotonic Action IDs, timestamps, input digests, execution durations, and cryptographic evidence receipts.

SECURITY TIER 8

Transactional Checkpoints

Multi-stage workflows capture workspace digests and state snapshots prior to destructive mutations, providing deterministic rollback anchors if an operation is aborted.

SECURITY TIER 9

Idempotent Crash Recovery

After an unexpected crash, Nexus combines Idempotency Tokens with physical OS introspection to determine actual state—cleaning up partial dirty writes instead of blindly re-running commands.

Sensitive Credential Shield

By default, Nexus blocks access to sensitive credential patterns before any request reaches the Runner:
.env*, *.pem, *.key, id_rsa*, credentials.json, and private tokens inside .git/config.
Even if an LLM attempts to read these files, the Nexus Enforcer denies the syscall at the policy layer and logs the blocked attempt in the Action Ledger.
